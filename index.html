What it does

Monitor. Control. Keep work moving.

DevRunX is being built for work that continues after you leave the screen. Observe activity, understand when something changes, inspect the useful context, and take a controlled action without returning to the originating machine.

01See activity

Bring relevant process, session, and event state into one operational view.

02Understand change

Surface the event or state transition that actually needs attention.

03Take action

Move from visibility to an intentional, controlled response when the system supports it.

How it works

Connect. Observe. Act.

DevRunX is designed around a simple operating loop rather than another dashboard you have to babysit.

01

Connect

Add a device or supported system and establish an authenticated relationship.

02

Observe

Receive real-time or near-real-time activity, events, state, and useful summaries.

03

Act

Run an approved action or command when intervention is actually needed.

Product principle

Context before control.

Remote control without context is risky and noisy. DevRunX is being shaped around understanding the state of work first, then exposing the smallest useful action.

State
What is running, waiting, completed, stopped, or needs attention.
Events
What changed and when, without forcing you to watch a live terminal continuously.
Actions
Controlled intervention tied to the session, device, and context that produced it.

The boundaries below are intentional. A data model or planned connector is not presented as a finished product surface.

Current codebase

Available foundation

Core identity and device/session foundations are present today:

  • Account registration/login foundation
  • Web account and profile surface
  • Device and session model
  • Time-limited pairing-code flow
  • Terminal-device pairing
  • Terminal-device session/token issuance
  • Role-aware device model
  • Backend rate-limiting foundations
Being built

In development

The operational experience is still being completed and verified:

  • Real-time session visibility
  • Terminal/event streaming
  • Richer device management
  • Controlled remote actions
  • Audit-log user experience
  • AI-generated session/event summaries
  • Robust reconnect/recovery behavior
  • Operational dashboard views
  • Notification workflows

Use cases

For the work that keeps going.

The point is not to stare at another console. It is to know when long-running work needs you — and when it does not.

01

A build is still running after you leave your desk.

Check its state and the useful output without reopening the original workstation.

02

An AI agent needs attention.

See that the run changed state and inspect the context before deciding what to do next.

03

A server process exits unexpectedly.

Surface the event and make the supported recovery path easier to reach.

04

A long-running task finishes.

Know that the job completed instead of repeatedly checking the machine that started it.

05

A deployment or automation changes state.

Bring the transition into the same operational context as the systems around it.

06

You are away from the originating machine.

Keep enough visibility to understand what is happening while the work continues elsewhere.
